# 知识库建设规则

## 1. 原始资料保护

- 原始文件位于项目既有目录；一律只读。不得编辑、覆盖、改名、删除或移动。
- 所有书目、笔记、索引、摘要、OCR副本、转码件和辅助文件都写入“我的人文知识库”或其他新建目录。
- 重复项只做标记，不删除、不合并原件；只有校验值相同才记为“内容完全重复”。

## 2. 阅读状态

- **待阅读**：尚未开始正文阅读。
- **初检可抽取文本**：有限页面抽查到文本；不等于全书可读或已读。
- **需OCR/视觉检查**：PDF抽样页缺少可提取文本；须检查页面图像或OCR。
- **当前无法完整读取**：存在明确解析/损坏/权限/格式障碍，须记录原因和影响范围。
- **部分阅读**：注明实际读到的章节/页码与日期。
- **已阅读**：需要记录本次真正覆盖的范围；只读目录/摘要不得标为整本已读。

## 3. 证据和解释分层

每条书籍笔记都分开记录：

- **作者明确观点**：可由原文直接支持，标章节、页码或PDF页序/段落。
- **文本概括**：对段落/章节论证的忠实转述，写明所依据位置。
- **跨书比较**：知识库内多本材料之间的支持、分歧、继承或互释，不能归到单一作者名下。
- **进一步推演**：AI或读者基于已有证据的推论，显式标为推演并说明前提。

无法核准页码时写章节、PDF页序或小节标题；禁止臆造出处、作者原话或书中内容。重要原文只摘录少量必要语句。

## 4. 单书档案

真正阅读一本书后，在 `01_单书档案/` 新建独立Markdown，采用项目约定的10节结构：基本信息；问题；核心观点；重要概念；论证逻辑；人物；历史背景；书间关系；与艺术的关系；原文证据；继续追问。区分“未核验书目信息”和“作者观点”。每个跨书关系都链接到对应单书档案/概念/人物/事件。

## 5. 概念、人物、历史、专题与知识链

- 反复出现且对解释有价值的概念，在 `04_核心概念/` 建立独立档案，记录各作者定义与分歧、文本位置、领域联系。
- 重要思想家、社会学家、艺术家与历史人物，在 `02_人物知识库/` 建档；不根据名字出现次数自动建档。
- 重要事件在 `03_历史事件/` 建档；区分事实描述、作者解释与本项目推演。
- 专题文件保留问题、已读证据、未决问题和引用来源。
- 跨学科链按“历史事件→社会结构→问题→理论回应→文化变化→艺术观念/实践/作品”逐段建证据。每一段都指向来源；推测性边用虚线/“待验证”标记。
- `12_知识地图/总知识地图.md` 是索引和关系概览，不代替单书证据。

## 6. 每次维护

开始前读取进度文件和上次未决点；完成后更新书目、单书状态、相关概念/人物/事件、知识链和总图。未经真正阅读不生成单书结论，不批量生成无出处摘要。


## 7. 机器可读数据（轻量层）

- Markdown档案是主要知识成果；实体JSON只保存稳定ID、名称、别名和确有必要的基本属性，不重复复制长篇论证，也不持续堆叠related_*关系数组。
- 重要关系优先写入`13_结构化数据/relations/relations.jsonl`，一行一条；只保留少量高价值关系，尽量记录书名、作者、章节、页码和文本位置。
- 每条新关系注明`evidence_type`（`author_explicit`、`textual_summary`、`cross_book_interpretation`或`ai_inference`）、`confidence`及`status`。正式知识使用`verified`；未核实的候选关系不得混入正式关系，若确需留存，必须标为`candidate`并写明待核事项。
- `cross_book_interpretation`与`ai_inference`不得表述成作者观点；没有可靠文本来源时不新建确定关系。
- 保留已有大型实体JSON及旧关系，不批量重写、删除或迁移。旧关系缺少status或精确出处时，按历史记录看待，不自动视为verified；今后自然增量过渡。
- 结构化时间不得挤占真实阅读、核心论证理解和原文证据整理。


## 8. 中文优先与人文版式

- 正文、标题、导航和状态说明以简体中文为主；原书题名、人名、作品名和核心术语首次出现时保留外文原名，便于回查与检索。
- 每份笔记开头先交代“这是何书/何篇、由谁撰写、读到哪里、目前能确认什么”。随后按“问题—论点—证据—关联—未决问题”组织。
- 标题层级保持稳定：一级标题标主题，二级标题标论题，三级标题标概念、证据或争论。一个文件尽量只承载一篇章节或一个专题。
- 语言清楚克制，允许有文气但不以修辞遮蔽证据；使用少量引言、目录、表格和关系图增强阅读节奏，避免符号堆饰和空泛赞语。
- 现存大型单书档案先作为历史汇总保留；新增章节采用独立短档案，并逐步补充目录/链接，不因排版重构丢失旧证据。 新条目优先套用 `章节与词条档案模板.md`。

## 9. 检索系统与 WeKnora 试点

- 现有 GitHub 仓库保存整理后的知识成果；WeKnora 是可选的 RAG/Agent/知识管理平台，不是单一模型或单一向量数据库。平台是否部署、连接哪个模型/数据库、导入哪些资料，分别记录，不互相推定。
- 试点优先使用中文导航、当前状态、建设规则、独立章节笔记、术语索引和专题/知识链；这类 Markdown 的章节结构和页码更利于人读及检索引用。
- 对历史超长汇总稿先验证分块、检索结果和页码引用，再考虑拆分/重建索引。关系 JSONL 和目录 CSV 默认作为结构化资料保存，不与论证性文本混合成普通自然语言索引。
- RAG 答案必须回显来源标题与原书页码/PDF页码，并允许用户回到原文核验。检索配置的效果通过一组可核对问题评估，不以“回答看起来合理”作为唯一标准。
- WeKnora 的 Agent Skills/记忆/图谱与 Codex 的本地 Skills/记忆分开管理；未确认的功能不写作“已部署”。
